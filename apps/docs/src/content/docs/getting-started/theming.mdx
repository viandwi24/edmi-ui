## Base, theme, radius and mode

Four independent knobs, all set on `<html>` and all plain CSS variables. Try them on the [Themes](/edmi-ui/themes/) page.

| Knob | How | Values | Changes |
| --- | --- | --- | --- |
| Mode | `class="dark"` | light (default), dark | every token |
| Base color | `data-base="…"` | `stone` (default, in `tokens.css`), `slate` | neutrals: surfaces, text, borders, the bevel colours, the neutral "ink" primary |
| Theme | `data-theme="…"` | `green` (default, in `tokens.css`), `ocean` | accent: brand, ring, charts, sidebar-primary; Ocean also recolors primary |
| Radius | `style="--radius: …"` | `0.625rem` default (`0.3rem` sharp to `1rem` round) | every radius |

```html
<html class="dark" data-base="slate" data-theme="ocean" style="--radius: 0.625rem">
```

Status colors (destructive, warning, success, info) never change with the base or theme. Positive values use
`success`, so they stay green in Ocean. **Stone · Green** is the default and needs no attributes. Slate and Ocean
are examples of how to customize: every base and theme is one CSS file, and components never reference a name.

## Registry themes

`@edmi-ui/theme` installs the default (Stone · Green) tokens. For every base and theme combination there is also a
`registry:theme` item with the complete light and dark color set. Installing one **replaces** the color variables in
`:root` and `.dark` (your radius is left alone), like shadcn's themes:

| Item | Base | Theme |
| --- | --- | --- |
| `theme-stone-green` | Stone | Green (same as the default) |
| `theme-stone-ocean` | Stone | Ocean |
| `theme-slate-green` | Slate | Green |
| `theme-slate-ocean` | Slate | Ocean |

## Runtime theming

Use the CSS route instead when your app lets end users switch base, theme, radius or mode at runtime.

**1. Load the files in this order.** Themes must win over bases for `primary`.

```css
@import "tailwindcss";
@import "@edmi-ui/tokens/tokens.css";          /* Stone · Green + dark */
@import "@edmi-ui/tokens/base/slate.css";      /* [data-base="slate"], .dark[data-base="slate"] */
@import "@edmi-ui/tokens/themes/ocean.css";    /* [data-theme="ocean"], .dark[data-theme="ocean"] */
@import "@edmi-ui/tokens/theme.css";
```

The defaults are also available as explicit rules, only needed to switch a nested scope back (see Scoped theming):
`@edmi-ui/tokens/base/stone.css` (`[data-base="stone"]`) and `@edmi-ui/tokens/themes/green.css` (`[data-theme="green"]`).
Load them in the same slots: the base before the themes.

Every base and theme ships light **and** dark blocks. Keys a file does not set fall back to the default.

**2. Switch with attributes on `<html>`.** Persist the choice in **cookies** and render the attributes on the server
so the first paint is already right (no flash).

```ts
// anywhere on the client
function setTheme(opts: { mode?: "light" | "dark"; base?: string; theme?: string; radius?: string }) {
	const root = document.documentElement;
	const set = (k: string, v: string) => {
		document.cookie = `${k}=${v}; path=/; max-age=31536000; samesite=lax`;
	};
	if (opts.mode) {
		root.classList.toggle("dark", opts.mode === "dark");
		set("edmi-mode", opts.mode);
	}
	if (opts.base) (root.dataset.base = opts.base), set("edmi-base", opts.base);
	if (opts.theme) (root.dataset.theme = opts.theme), set("edmi-accent", opts.theme);
	if (opts.radius) {
		root.style.setProperty("--radius", `${opts.radius}rem`);
		set("edmi-radius", opts.radius);
	}
}
```

**React or Vue with Vite (client only).** An inline script in `index.html` applies the cookies before first paint:

```html
<script>
	(function () {
		var c = {};
		document.cookie.split("; ").forEach(function (p) {
			var i = p.indexOf("=");
			c[p.slice(0, i)] = p.slice(i + 1);
		});
		var r = document.documentElement;
		if (c["edmi-mode"] === "dark") r.classList.add("dark");
		if (c["edmi-base"]) r.dataset.base = c["edmi-base"];
		if (c["edmi-accent"]) r.dataset.theme = c["edmi-accent"];
		if (c["edmi-radius"]) r.style.setProperty("--radius", c["edmi-radius"] + "rem");
	})();
</script>
```

**SvelteKit (server-rendered).** Read the cookies in `hooks.server.ts` and fill placeholders in `app.html`:

```ts
// src/hooks.server.ts
import type { Handle } from "@sveltejs/kit";

export const handle: Handle = ({ event, resolve }) => {
	const get = (k: string) => event.cookies.get(k) ?? "";
	return resolve(event, {
		transformPageChunk: ({ html }) =>
			html
				.replace("%edmi.mode%", get("edmi-mode") === "dark" ? "dark" : "")
				.replace("%edmi.base%", get("edmi-base") || "stone")
				.replace("%edmi.accent%", get("edmi-accent") || "green")
				.replace("%edmi.radius%", `${get("edmi-radius") || "0.625"}rem`),
	});
};
```

```html
<!-- src/app.html -->
<html lang="en" class="%edmi.mode%" data-base="%edmi.base%" data-theme="%edmi.accent%" style="--radius: %edmi.radius%">
```

**Vue with Nuxt (or any SSR).** Same idea: read the cookies on the server (`useCookie("edmi-mode")`, …) and render them
with `useHead({ htmlAttrs: { class, "data-base", "data-theme", style } })` so the HTML arrives themed. In a plain Vite
app use the inline script above.

**Scoped theming.** Any subtree can carry its own attributes and `class="dark"`, for example an always-dark sidebar
inside a light app. Put `class="dark" data-base="slate"` on that element; its tokens (and `dark:` styles) resolve inside it only.
To switch a scope back to the defaults inside a Slate · Ocean app, set `data-base="stone" data-theme="green"` on it (with
`base/stone.css` and `themes/green.css` loaded). The Stone file also resets `primary`; the Green file leaves `primary` to the base.

### Create your own base or theme

Copy a file, change the values, keep the selectors:

Run `bun scripts/gen-default-scopes.ts` after changing `tokens.css` or adding a base or theme: it regenerates
`base/stone.css` and `themes/green.css` (a test fails when they are stale).

1. New base: copy `packages/tokens/src/base/slate.css` to `base/<name>.css` and change the neutrals (`[data-base="<name>"]` and `.dark[data-base="<name>"]`).
2. New theme: copy `themes/ocean.css` to `themes/<name>.css` and change the accent keys (`[data-theme="<name>"]` and `.dark[data-theme="<name>"]`).
3. Import it after `tokens.css` and set the attribute on `<html>`.

In this repository, dropping the file in those folders is all it takes: the registry generates the matching
`theme-<base>-<theme>` items and the Themes page offers the new option.

## Elevation tokens

Depth is the [elevation system](/edmi-ui/getting-started/elevation/). Components are flat unless they take an
`elevation` level (`sunken`, `flat`, `raised`, `floating`) from the prop or from an `ElevationProvider`. The visuals
come from tokens that exist for light and dark and for every base color, so a theme never has to touch them.

| Token | Role |
| --- | --- |
| `--bv-ring` | inner rim of the bevel |
| `--bv-top` | 1px top highlight of the bevel |
| `--bv-out` | dark hairline around a raised or floating surface |
| `--bv-face-a`, `--bv-face-b` | neutral face gradient (top to bottom) |
| `--bv-float` | the one soft drop of a floating layer |
| `--sk-bg`, `--sk-bd`, `--sk-sh` | sunken well: fill, border, soft inset |
| `--r1-p`, `--r1-p-face`, `--r1-s`, `--r1-s-face` | raised (+1) button edge and face, primary and neutral |
| `--fl-p`, `--fl-p-face`, `--fl-s`, `--fl-s-face` | floating (+2) button edge and face, primary and neutral |

`@edmi-ui/tokens/theme.css` maps them to Tailwind utilities: `shadow-raised`, `shadow-floating`, `shadow-sunken`,
`shadow-btn-raised-primary|neutral|color`, `shadow-btn-float-primary|neutral|color`, `shadow-btn-sunken-filled`,
`shadow-pressed`, `shadow-pressed-float`, `shadow-thumb`, `shadow-group-float`, plus `bg-sk-bg` and `border-sk-bd`.
Components use these; do not hard-code shadows. Gradient faces on a bordered control use a transparent border and
`[background-origin:border-box]`.

The old lip tokens (`--lip`, `--lip-strong`, `--*-lip`, `--*-edge`, `--*-shade`, `--card-hi`, `--outline-*`) are kept
only for compatibility. Components no longer use them.

### Dark ladder

The stone dark palette uses a clearer ladder so surfaces separate without black blocks: background `#121214`, card
`#1c1c20`, popover `#232328`, secondary `#2a2a30`, border and accent `#303036`, input `#48484f`, muted text `#9b9ba3`.
Slate keeps its own dark values. In dark mode depth comes from the bevel hairline and a faint top highlight, and the
sunken well is a soft inset darker than the card.

### Layered mode in the docs

The landing page and the Themes page preview switch between **Flat** and **Layered**: the showcase is wrapped in an
`ElevationProvider` and the toggle flips its `mode`. Your app does the same with one wrapper.
